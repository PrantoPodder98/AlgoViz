01 · Unweighted Graph · Queue · Optimal

BFS — Breadth-First Search

🚨 City Rescue Mission — Fire Station (S) must reach Rescue Site (★) in fewest streets

The Core Idea

BFS uses a Queue (FIFO). It explores all nodes at distance 1 before distance 2, then distance 3 — like ripples spreading outward from a stone dropped in water. Because it always processes closer nodes before farther ones, the first time it reaches any node is via the shortest possible path.

Graph — 13 nodes, unweighted

Nodes: S, A, B, C, D, E, F, G, H, I, J, K, ★ Adjacency list: S → A, B, D A → S, C, D, F B → S, E, H C → A, F D → S, A, G, E E → B, D, H F → A, C, I, J G → D, J, K H → B, E, K I → F, ★ J → F, G, ★ K → G, H, ★ All edges have equal cost (1 hop each)
Step-by-step execution
0
Initialise — Push S onto Queue
Mark S as visited. Enqueue S. Set parent[S] = null.
Queue: [S] | Visited: {S} | Depth: 0
1
Dequeue S (depth 0) → Discover A, B, D
Pop S from the front of the queue. Check neighbours: A, B, D — all unvisited. Mark them visited, set parent[A]=S, parent[B]=S, parent[D]=S, and enqueue them.
Queue: [A, B, D] | Visited: {S,A,B,D} | Depth: 1
2
Dequeue A (depth 1) → Discover C, F
Neighbours of A: S (visited), C (new), D (visited), F (new). Add C and F. parent[C]=A, parent[F]=A.
Queue: [B, D, C, F] | Visited: {S,A,B,D,C,F}
3
Dequeue B (depth 1) → Discover E, H
Neighbours: S (visited), E (new), H (new). parent[E]=B, parent[H]=B.
Queue: [D, C, F, E, H]
4
Dequeue D (depth 1) → Discover G
Neighbours: S, A (both visited), G (new), E (already queued/visited). Add G. parent[G]=D.
Queue: [C, F, E, H, G]
5
Dequeue C, F, E, H, G (depth 2) — continue discovering
Dequeue C → discovers nothing new. Dequeue F → discovers I and J. parent[I]=F, parent[J]=F. Dequeue E, H, G → discover K. parent[K]=G or H (first arrival wins).
Queue: [I, J, K] | Depth: 3 nodes now known
6

Neighbour of I includes ★. First time ★ is reached → we have found the goal! parent[★]=I. Stop.
★ found at depth 3!
✓

Walk back: ★ ← I ← F ← A ← S. Reverse to get forward path.
S→ A→ F→ I→ ★

Why is S → A → F → I → ★ the shortest path? (Exam answer)

This path has 4 hops. BFS guarantees this is optimal for an unweighted graph because:

(1) BFS processes all depth-1 nodes (A, B, D) before any depth-2 node.
(2) It processes all depth-2 nodes (C, F, E, H, G) before any depth-3 node.
(3) The first time ★ is discovered (by I at depth 3), that is the minimum possible depth — because every shorter path (depth 1 or 2) has already been fully explored and ★ was not found there.
(4) Parent pointers record which node discovered each node first, giving us the exact route that achieved this minimum depth.

There is no path of length 3 from S to ★ in this graph. BFS proves this by exhausting all depth-3 discoverable nodes before finding ★.

📝 Exam tip: In BFS questions, always write: (1) queue state after each dequeue, (2) which node was dequeued, (3) which new nodes were added. At the end, trace the parent pointer chain backwards from goal to start, then reverse it.
02 · Unweighted Graph · Stack · NOT Optimal

DFS — Depth-First Search

🧭 Cave Network — Explorer enters at S, seeks Treasure (★)

The Core Idea

DFS uses a Stack (LIFO). It dives as deep as possible along one branch before backtracking. It finds a path, but does NOT guarantee the shortest path — it commits to one direction greedily without checking alternatives first.

Graph — 13 nodes, unweighted

Nodes: S, A, B, C, D, E, F, G, H, I, J, K, ★ Adjacency list: S → A, B, D A → S, C, D, G B → S, E, F C → A, G D → S, A, H E → B, H, I F → B, I G → A, C, J H → D, E, J, K I → E, F, K J → G, H, ★ K → H, I, ★
Step-by-step execution (DFS pushes neighbours in reverse so first logical neighbour is on top)
0
Initialise — Push S onto Stack
Stack = [S]. parent[S] = null.
Stack (top→): [S]
1
Pop S → Push D, B, A (A on top)
Mark S visited. Neighbours: A, B, D. Push in reverse order → D, B, A. A is on top and explored next. parent[A]=S, parent[B]=S, parent[D]=S.
Stack: [D, B, A] → next: A
2
Pop A → Push G (C and D skipped/visited)
Mark A visited. Neighbours: S (visited), C, D (visited), G. Push C then G. G is now on top. parent[G]=A, parent[C]=A.
Stack: [D, B, C, G] → next: G
3
Pop G → Push J (C already queued)
Mark G visited. Neighbours: A (visited), C (already in stack), J. Push J. parent[J]=G.
Stack: [D, B, C, J] → next: J
4
Pop J → Discovers ★!
Mark J visited. Neighbours: G (visited), H, ★. ★ is found! parent[★]=J. Stop immediately.
★ found!
✓
Trace back parent pointers
★ ← J ← G ← A ← S. Reversed:
S→ A→ G→ J→ ★

Is S → A → G → J → ★ the shortest path? — Full explanation

Yes — in this particular graph, 4 hops is actually the minimum possible. We can verify: the only paths from S to ★ require at least 4 edges (S is separated from ★ by 4 levels of the graph). So DFS happened to find the shortest path here — by coincidence, not by design.

However — DFS does NOT guarantee this in general:
(1) DFS chose S→A because A was the first neighbour pushed. It went deep: A→G→J→★. This route happened to be 4 hops.
(2) DFS never checked S→B or S→D before finding ★. If ★ had been reachable via S→D→H→★ (3 hops), DFS would have missed it and reported the longer path.
(3) In an exam: say "DFS found path S→A→G→J→★ (4 hops). This is the minimum depth in this graph, but DFS cannot guarantee optimality in general — it committed to the A branch without exploring alternatives."

BFS vs DFS — Key difference for exam

BFS: explores level by level → guaranteed shortest hop count → uses more memory (whole frontier in queue).
DFS: dives deep first → finds a path quickly → uses less memory (only current path on stack) → NOT optimal — may find a longer path if it picks the wrong branch first.

📝 Exam tip: In DFS questions, write the stack state after every push/pop. Note which nodes you skip because they're "already visited." At the end, say explicitly: "DFS found path X. This is NOT guaranteed to be the shortest path because DFS does not explore all paths at each depth level before going deeper."
03 · Unweighted · Stack · Depth Limit = 3

DFDB — Depth-Limited Search

🏢 Building Search — Security starts at Reception (S), finds Child (★), limit = 3 floors

The Core Idea

DFDB is DFS with a hard depth cutoff. Any node at depth > L is pruned — we simply refuse to go there. This is useful when we know the goal must be "nearby." The trade-off: if the goal is deeper than L, we fail to find it entirely. IDDFS (Iterative Deepening) solves this by running DFDB with L = 0, 1, 2, 3 … until found.

Graph — 12 nodes, depth limit L = 3

Nodes: S, W1A, W1B, W2A, W2B, W2C, W3A, W3B, W3C, W4A, W4B, ★ Tree structure (depth): S (d=0) ├── W1A (d=1) ── W2A (d=2) ── W3A (d=3) ── W4A (d=4) [PRUNED] │ └── W2B (d=2) ── W3A, W3B (d=3) ── W4B (d=4) [PRUNED] │ └── ★ (d=4) [PRUNED from W3B] └── W1B (d=1) ── W2B (d=2) ── W3B (d=3) ── ★ via W3B (depth 4) └── W2C (d=2) ── W3C (d=3) ── ★ (depth 4 — PRUNED) Edges: S-W1A, S-W1B, W1A-W2A, W1A-W2B, W1B-W2B, W1B-W2C, W2A-W3A, W2B-W3A, W2B-W3B, W2C-W3C, W3A-W4A, W3B-W4B, W3B-★, W3C-★, W4A-★, W4B-★
Step-by-step execution with depth tracking
0
Initialise — Stack = [(S, depth=0)]
Stack: [(S,0)] | Pruned: 0
1–3
Explore S→W1A→W2B→W3B (depths 0,1,2,3)
Each node is within limit. Pop S (d=0) → push W1B(d=1), W1A(d=1). Pop W1A(d=1) → push W2B(d=2), W2A(d=2). Pop W2A(d=2) → push W3A(d=3). Pop W3A(d=3) — at limit, PRUNE W4A. Pop W2B(d=2) → push W3B(d=3), W3A (already visited).
Pruned so far: W4A (and its subtree)
4
⛔ PRUNE: W3B is at depth 3 — W4B and ★ would be depth 4 → skipped
We're at W3B (d=3). Neighbours are W4B and ★ — both would be at d=4 which exceeds limit=3. We do NOT explore them. This is pruning in action.
Pruned: W4A, W4B, ★ (from W3B)
5
Continue via W1B → W2C → W3C
Pop W1B(d=1) → discover W2C(d=2). Pop W2C(d=2) → discover W3C(d=3). Pop W3C(d=3) → at limit. ★ is neighbour at d=4 → PRUNED.
★ is pruned again from W3C route.

DFDB FAILS — ★ is at depth 4, limit is 3
The child (★) is always connected to nodes at depth 4 (W3B, W3C, W4A, W4B). Since our limit is 3, DFDB cannot reach ★ and reports failure.
Result: GOAL NOT FOUND within depth limit 3

Why DFDB fails here — and what to write in the exam

The depth limit is 3, but ★ is only reachable at depth 4 (e.g. S→W1B→W2C→W3C→★). DFDB prunes everything beyond depth 3, so ★ is never expanded.

In the exam: "DFDB with L=3 fails to find ★ because the shortest path to ★ requires 4 hops. All routes to ★ pass through depth-3 nodes (W3B, W3C), but ★ itself is at depth 4. The algorithm prunes it. To solve this, increase L to 4, or use Iterative Deepening DFS (IDDFS) which tries L=0, 1, 2, 3, 4, … automatically."

📝 Exam tip: When you show DFDB working, write the depth number next to each node: (S,0), (W1A,1), (W2B,2), (W3B,3). Mark PRUNED clearly when a node would exceed L. Count how many nodes were pruned vs. how many would have been explored without the limit.
04 · Weighted Graph · Priority Queue · NOT Optimal

Greedy Best-First Search

🏥 Hospital Emergency — Ambulance (S) must reach Hospital (★) fast

The Core Idea

Greedy always picks the node with the lowest h(n) — the heuristic estimate of distance to goal. It looks at where the goal appears to be and greedily rushes toward it. It ignores actual travel cost (g). This makes it fast but unreliable — a node that looks close might require expensive roads to reach it.

Graph — 12 nodes, weighted edges, with h(n) values

h(n) = estimated straight-line distance to hospital ★ Node h-values: S=14 A=10 B=11 C=7 D=8 E=12 F=5 G=4 H=9 I=3 J=2 ★=0 Edges (with weights): S-A:3 S-B:4 S-D:6 A-C:2 A-D:5 B-E:3 B-H:7 C-F:4 D-F:3 D-G:5 E-H:4 F-I:3 G-I:6 G-J:3 H-J:8 I-★:4 J-★:2

Is S → D → G → J → ★ the optimal path? — Full explanation

In this specific graph, the Greedy path S→D→G→J→★ has cost 16. The true optimal is S→A→C→F→I→★ which also costs 16 (3+2+4+3+4). So Greedy accidentally found a path with optimal cost here.

However — this is purely coincidental. Greedy is NOT optimal in general because:
(1) Greedy picked D (h=8) over A (h=10) purely because D looks closer. But the road S→D costs 6, while S→A costs only 3. Greedy did not check this.
(2) Greedy picked G (h=4) over F (h=5), but the road D→G costs 5 while D→F costs only 3. Again ignored.
(3) If the graph had a slightly longer J→★ edge, Greedy's path would become suboptimal while S→A→C→F→I→★ remains optimal.

In the exam, always write: "Greedy found path S→D→G→J→★ (cost 16). This path is NOT guaranteed optimal. Greedy used only h(n) estimates and ignored actual edge weights g(n). A* uses f(n) = g(n) + h(n) to guarantee the optimal result."

📝 Exam tip: In Greedy questions, write out the open list after each expansion, sorted by h. Show which node you pick each time and why (lowest h). Explicitly state: "Greedy ignores actual costs — it only uses h(n)." Calculate the actual total cost at the end and compare to A* to show it may not be optimal.
05 · Weighted Graph · Priority Queue · OPTIMAL (admissible h)

A* Search

🗺️ GPS Navigation — City S to Airport ★, minimise total km driven

The Core Idea

f(n) = g(n) + h(n)

g(n) = actual cost from start to n (known exactly as we travel)
h(n) = heuristic estimate of cost from n to goal (must be admissible: never overestimate)
f(n) = best estimated total cost of a path through n

A* always expands the node with the lowest f(n). Because h is admissible, the first time we expand the goal node, we have found the true optimal path — we cannot do better.

Graph — 13 nodes, weighted, with h(n) values

h(n) = admissible heuristic (straight-line estimate to Airport ★) Node h-values: S=20 A=16 B=17 C=12 D=11 E=14 F=8 G=7 H=10 I=5 J=4 K=2 ★=0 Key edges (weight): S-A:4 S-B:6 S-D:9 A-C:3 A-D:5 B-E:4 B-H:8 C-F:5 D-F:4 D-G:7 E-G:6 E-H:5 F-I:4 G-I:6 G-J:5 H-J:9 I-K:3 I-★:8 J-K:5 J-★:7 K-★:3

Why is A* guaranteed optimal? (Exam answer)

(1) Admissible heuristic: h(n) never overestimates — it is always ≤ true remaining cost. This means f(n) = g(n)+h(n) is always ≤ true total cost through n.
(2) When A* expands a node, it has already found the cheapest possible path to that node. Any later path via a different route would have higher g (because that would have been expanded earlier if cheaper).
(3) Key parent update: At step 7, ★ was already in the open list via I (g=24). When K was expanded, a cheaper route to ★ (g=22) was found, so the parent was updated to K. This is how A* avoids committing to suboptimal partial paths.
(4) When ★ is finally expanded (not just discovered), its g=22 is the true minimum — proven because every other open node has f ≥ 22.

📝 Exam tip: In A* questions, maintain a table: Node | g | h | f | Parent. Update it after every expansion. Show when a node's g value is updated (improved). State clearly: "A* is optimal because h is admissible. When ★ is expanded, g=22 is the minimum possible because all other open nodes have f ≥ 22."
06 · Combinatorial Optimisation · NP-Hard · Heuristics

TSP — Travelling Salesperson Problem

📦 Delivery Driver — Warehouse (W) + 9 delivery addresses, minimise total route distance

The Core Idea

Visit every city exactly once and return to start, with minimum total distance. With 10 cities: 9! = 362,880 possible routes. With 20 cities: 60 quadrillion. We cannot try them all — we use heuristics that give "good enough" answers fast.

Cities (10 total including Warehouse W)

W = Warehouse (start + end) 1 = Northwick 2 = Eastgate 3 = Old Quarter 4 = Riverside 5 = Southpark 6 = Millbrook 7 = Crossroads 8 = Hilltop 9 = Docklands All cities are directly connected (complete graph). Distance = Euclidean distance between their positions.
Three approaches compared
①
Phase 1 — Random Route (baseline)
Order: W→3→6→1→4→7→2→9→5→8→W. Lines criss-cross the map — massive waste of travel. Used only as a worst-case baseline.
Quality: ❌ Worst | Crossing edges everywhere
②
Phase 2 — Nearest Neighbour Algorithm (NNA)
Rule: At each step, go to the nearest unvisited city.
Step 1: From W, find nearest unvisited → Hilltop (8).
Step 2: From 8, find nearest unvisited → Northwick (1).
Step 3: From 1, find nearest → Eastgate (2).
Continue until all cities visited, then return to W.
Much shorter than random — fewer crossing edges.
Quality: ✓ Better | ~20-25% above optimal typically
③
Phase 3 — 2-opt Improvement
Rule: For every pair of edges (A→B) and (C→D), check if swapping them — replacing with (A→C) and (B→D) — makes the route shorter. If yes, make the swap (reverse the segment between B and C). Keep swapping until no further improvement is possible.
Why it works: Two crossing edges can ALWAYS be "uncrossed" to get a shorter total distance — this is a geometric fact.
Quality: ✓✓ Best of three | Locally optimal (no 2-edge swap can improve it)

Key exam points about TSP

Why NP-Hard? No known algorithm can find the OPTIMAL tour in polynomial time for large n. Brute force checks all (n-1)!/2 tours — exponential. Even with 20 cities that's 60 quadrillion routes.

NNA is greedy: It makes the locally best choice (nearest city) at each step without looking ahead. The last few cities added often require long "back-fill" legs because NNA painted itself into a corner.

2-opt is local search: It improves an existing tour. It will NEVER make a tour worse. But it only finds a local optimum — it cannot guarantee finding the global minimum.

In the exam: Show the NNA step by step (current city → nearest unvisited → distance). Then explain what 2-opt does (identify crossing edges → swap → shorter route). State: "2-opt gives a locally optimal solution — no single 2-edge swap can improve it further, but the true global optimum may still be shorter."

📝 Exam tip: For NNA, always show a table: Step | Current City | Nearest Unvisited | Distance. For 2-opt, draw the crossing edges and show the "uncrossed" version. Always say "NNA ≈ 20-25% above optimal; 2-opt improves this but cannot guarantee the global minimum."
07 · State-Space Search · BFS · Optimal (fewest moves)

8-Puzzle — BFS Solver

🧩 Slide tiles on a 3×3 board from start arrangement to goal

The Core Idea

Each board configuration is a node. Each legal tile slide is an edge. BFS finds the sequence of slides with the fewest moves. State space = up to 181,440 configurations (9!/2). BFS guarantees finding the minimum number of moves.

Start State

┌───┬───┬───┐ │ 1 │ 2 │ 3 │ ├───┼───┼───┤ │ 4 │ 5 │ 6 │ ├───┼───┼───┤ │ 7 │ 8 │ │ └───┴───┴───┘ (ordered 1–8, blank bottom-right)

From centre blank, legal slides: tile 2 (down), tile 4 (right), tile 5 (up), tile 6 (left). All 4 children added to BFS queue.

BFS explored all 1-move states before any 2-move state. The goal was reached at depth 2. No 1-move solution exists (only one tile differs from goal: 5 and blank swapped), so 2 is optimal.

Why is 2 moves optimal? (Exam answer)

BFS explores all states reachable in 1 move before exploring any state reachable in 2 moves. It checked all 4 possible 1-move states from the start — none of them was the goal. It then checked 2-move states — and found the goal immediately. Since BFS found it at depth 2, no solution of length 1 or 0 exists, proving 2 is the minimum.

📝 Exam tip: Draw the board after every move. State which tile slides and in which direction. Count the number of misplaced tiles (Manhattan distance) to justify why the answer can't be shorter. Show BFS layers: "depth 0 = start, depth 1 = 4 states (all checked, none = goal), depth 2 = found goal."
08 · Classification · Tree Traversal · Rule-based

Decision Tree — Bank Loan Application

🏦 Applicant Sarah applies for a loan — decision tree classifies: Approve / Reject / Conditional

The Core Idea

A Decision Tree makes a sequence of binary questions (yes/no). Each internal node is a question; each leaf is a decision. To classify, start at the root and follow YES or NO branches based on the applicant's data until you reach a leaf.

Why Decision Trees are useful — Exam points

(1) Interpretable: You can trace exactly why a decision was made (unlike neural networks — "black boxes").
(2) Fast classification: O(depth) to classify any instance — just follow branches top to bottom.
(3) Handles mixed data: Both numeric thresholds (credit > 700) and categorical features (employed Y/N).
(4) Overfitting risk: Deep trees memorise training data. Pruning (cutting shallow branches) is used to improve generalisation.
(5) Greedy construction: Trees are built top-down using information gain or Gini impurity to choose which feature to split on at each node.

📝 Exam tip: When tracing a decision tree, write each question as Q1, Q2, Q3 and explicitly write the answer (YES/NO) and which branch you take. At the leaf, state the final decision and count how many questions were needed. If asked "could a different tree structure reach the same decision?" — YES, tree structure depends on the training algorithm and split criterion.

Exam Cheat Sheet — What to Write


For every search algorithm, your exam answer must include:

BFS Answer Structure

  • Initial queue state
  • After each dequeue: node popped, neighbours found, queue updated
  • State "all depth-N nodes explored before depth-N+1"
  • Traceback via parent pointers
  • "Optimal because first discovery = minimum depth"

DFS Answer Structure

  • Stack state after each push/pop
  • Note dead-ends as "backtrack"
  • Show parent pointers building up
  • Traceback path
  • Always say: "NOT guaranteed optimal"

A* Answer Structure

  • Table: Node | g | h | f | Parent
  • Show f=g+h calculation for every node
  • Show any parent updates when cheaper path found
  • When goal expanded: state g = optimal cost
  • "Optimal because h is admissible"

Greedy Answer Structure

  • Open list sorted by h(n) after each step
  • Show which node chosen and why (lowest h)
  • Calculate actual total cost at end
  • Always say: "NOT guaranteed optimal — ignores g(n)"
  • Compare with A* optimal

Critical facts to memorise

Optimality — The Key Exam Question

BFS is optimal for unweighted graphs — fewest edges. Not optimal if edges have different weights.
A* is optimal for weighted graphs IF h(n) is admissible (never overestimates true cost).
Greedy is NOT optimal — ignores actual cost g(n), only uses estimate h(n).
DFS is NOT optimal — may find a longer path if it dives down the wrong branch first.
DFDB is NOT optimal — may not even find the goal if it's deeper than limit L.
NNA (TSP) is NOT optimal — greedy local choice doesn't guarantee minimum tour.
2-opt is locally optimal — no 2-edge swap improves it, but global optimum may differ.

Data Structures

BFS → Queue (FIFO): add to back, remove from front → level-by-level exploration
DFS / DFDB → Stack (LIFO): add to top, remove from top → deep exploration
Greedy / A* → Priority Queue: always remove the node with lowest priority value
  Greedy priority = h(n)   |   A* priority = f(n) = g(n) + h(n)

Common Exam Mistakes

❌ Saying "DFS found the shortest path" — should say "DFS found a path but it's not guaranteed shortest."
❌ Saying "Greedy is optimal" — it is not; it ignores actual edge costs.
❌ Forgetting to update parent pointers in A* when a cheaper path is found.
❌ In BFS/DFS, adding a node to queue/stack AGAIN if it was already visited.
❌ Confusing "complete" (always finds a solution if one exists) with "optimal" (finds the BEST solution).
❌ In TSP, claiming 2-opt gives the globally optimal tour — it gives a locally optimal one.
❌ Forgetting to return to start in TSP (the tour must be a cycle: W→…→W).

📝 Most important exam sentence: For any algorithm that is NOT optimal, always write: "Algorithm X found path P. This is not guaranteed to be optimal because [reason specific to algorithm]. To find the guaranteed optimal path, use [better algorithm] instead."
